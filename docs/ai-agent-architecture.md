# ShopMate AI — Agent Architecture, Knowledge Base & Developer Guide

## Executive Overview
ShopMate AI is not a simple chatbot that outputs unstructured text. It is an **Autonomous Shopping Assistant & Orchestrator** capable of reasoning across multiple knowledge sources, triggering live database operations, validating business rules, and driving rich interactive UI components on the client.

As a developer, your primary mental model is:
> **The AI Agent does not store the website in its head. It is an orchestrator equipped with specialized tools, querying dedicated data layers when and only when required.**

## 1. The 4 Knowledge Tiers of the Agent

The agent draws from four distinct, specialized knowledge layers:

```text
┌───────────────────────────────────────────────────────────────────────────────┐
│                     THE 4 KNOWLEDGE TIERS OF SHOPMATE AI                      │
├─────────────────────────┬───────────────────────────────────┬─────────────────┤
│ Tier & Type             │ Data Store                        │ Speed & Latency │
├─────────────────────────┼───────────────────────────────────┼─────────────────┤
│ 1. Semantic / Style     │ pgvector (jersey_embeddings)      │ ~5ms - 15ms     │
│ 2. Live Operational     │ PostgreSQL Relational (Prisma)    │ ~1ms - 5ms      │
│ 3. Store Policies & FAQ │ System Prompt & Business Rules    │ 0ms (In-Memory) │
│ 4. Working Memory       │ Redis Key-Value Store (ioredis)   │ < 1ms           │
└─────────────────────────┴───────────────────────────────────┴─────────────────┘
```

### Tier 1: Semantic & Style Discovery (`jersey_embeddings` in PostgreSQL via `pgvector`)
* **Under the Hood:** High-dimensional mathematical coordinates (768 floating-point numbers) generated by Google's `text-embedding-004` model.
* **What it Solves:** Fuzzy, emotional, or visual queries where exact keywords fail.
  * *"Show me a vintage kit with gold collar detailing."*
  * *"A sleek dark away kit for casual street style."*
* **PostgreSQL Query Pattern:**
  ```sql
  SELECT j.id, j.title, j.base_price, 1 - (je.embedding <=> $1::vector) AS similarity
  FROM jersey_embeddings je
  JOIN jerseys j ON j.id = je.jersey_id
  ORDER BY je.embedding <=> $1::vector ASC
  LIMIT 5;
  ```
  *(Where `<=>` is the cosine distance operator).*

### Tier 2: Live Operational State (PostgreSQL Relational Tables via Prisma)
Embeddings are static snapshots of text descriptions; they cannot tell you what is happening this second. Live operational truth comes from Prisma queries:
* **`clubs`:** Official club names, leagues (EPL, La Liga, Serie A), and transparent badge CDN links.
* **`jerseys`:** Server-authoritative base pricing ($79.99), official season strings (`2019/20`), kit type (`HOME`, `AWAY`, `THIRD`), and verified media assets.
* **`jersey_variants`:** Real-time stock counts by size ($S: 14$, $M: 20$, $XXL: 0$). Ensures the agent never sells out-of-stock sizes.
* **`carts` & `cart_items`:** What the customer currently has loaded in their session.
* **`orders` & `order_items`:** Order status tracking and history.

### Tier 3: Store Rules, Policies & Business Logic (Agent System Instructions)
Certain operational rules must never be fetched from database tables because they are static domain policies. These are injected into the agent's system instructions:
* **Custom Printing Rules:** Player name & number printing is a flat **+$15.00**; tournament/league sleeve badges are a flat **+$5.00**.
* **Return Policy:** 30-day window for unworn items with original tags. Customized kits with player/personal printing are strictly **non-refundable** unless defective.
* **Shipping Policy:** Standard 3–5 business days ($5.99 flat, free on orders over $100).
* **Sizing Advice:** Modern athletic kits have a slim fit. Advise relaxed-fit shoppers to size up one tier.

### Tier 4: Working Session Memory (Redis via `ioredis`)
* **Under the Hood:** A TTL-expiring Redis list storing the rolling 10 to 20 conversation turns keyed by `session:<sessionId>:chat`.
* **What it Solves:** Multi-turn reference resolution.
  * User: *"Show me Real Madrid kits."*
  * Agent: Returns Home and Away options.
  * User: *"Add that away one to my cart in size Large."*
  * Without Tier 4, the agent would ask: *"Which kit do you mean?"*. With Tier 4, it inspects recent context and immediately resolves "that away one" to the Real Madrid 2019/20 Away jersey.

## 2. Agent Capabilities & The Function Calling Loop

The agent does not access the raw database directly. Instead, we expose declared JavaScript/TypeScript functions (Tools) to Gemini. The model acts as the reasoning brain: it inspects user intent, selects which tool to run, receives the structured output, and decides the next step.

```text
               ┌──────────────────────────────────────────────┐
               │              User Enters Query               │
               │ "Find an Italian home kit and add size M"    │
               └──────────────────────┬───────────────────────┘
                                      │
                                      ▼
               ┌──────────────────────────────────────────────┐
               │    Gemini LLM (Function Calling Engine)      │
               │ 1. Evaluates conversation history (Redis)    │
               │ 2. Detects required actions                  │
               └──────────────────────┬───────────────────────┘
                                      │
              ┌───────────────────────┴───────────────────────┐
              │                                               │
              ▼                                               ▼
   [ Step 1: Discovery Tool ]                    [ Step 2: Verification Tool ]
   searchCatalogSemantically({                   checkJerseyStock({
     query: "Italian home kit"                     jerseyId: "ac-milan-19-20",
   })                                              size: "M"
              │                                  })
              │                                               │
              ▼                                               ▼
   Postgres pgvector Query                       Prisma variants Query
   Returns: AC Milan & Inter                     Returns: stockQuantity = 18
              │                                               │
              └───────────────────────┬───────────────────────┘
                                      │
                                      ▼
                         [ Step 3: Action Tool ]
                         addToCart({
                           sessionId: "sess_abc123",
                           variantId: "var_milan_m",
                           quantity: 1
                         })
                                      │
                                      ▼
               ┌──────────────────────────────────────────────┐
               │        Server-Sent Events (SSE) Stream       │
               │ 1. Emits UI_EVENT: CART_UPDATED              │
               │ 2. Streams conversational confirmation text  │
               └──────────────────────────────────────────────┘
```

### Complete Tool Inventory

| Tool Name | Tool Purpose | Input Schema (Zod) | Output |
| :--- | :--- | :--- | :--- |
| **`searchCatalog`** | Semantic vector search for kits | `{ query: string, maxResults?: number }` | Top matching jerseys with prices & images |
| **`checkStock`** | Live inventory lookup per size | `{ jerseyId: string, size: 'S'\|'M'\|'L'\|'XL'\|'XXL' }` | Exact quantity available + in-stock boolean |
| **`calculatePrice`** | Server-verified price calculation | `{ jerseyId: string, hasBadge: boolean, customName?: string }` | Total calculated price with itemized breakdown |
| **`addToCart`** | Adds item with customization to cart | `{ variantId: string, quantity: number, customName?: string, customNumber?: number, sleeveBadge?: string }` | Updated cart item snapshot |
| **`viewCart`** | Reads customer's current cart | `{ sessionId: string }` | List of items, quantities, subtotal, and tax |

## 3. How the Agent Controls the UI (Generative UI via SSE)

In standard chat implementations, an AI outputs raw text. In ShopMate AI, the agent streams **Structured UI Payloads** alongside natural language over Server-Sent Events (SSE).

### The SSE Stream Contract
When the backend processes a tool execution, it writes event blocks to the HTTP stream:

```http
HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive

event: ui_component
data: {"type":"PRODUCT_CAROUSEL","items":[{"id":"juv-19-20-h","title":"Juventus 19/20 Home","price":89.99,"imageUrl":"https://r2.thesportsdb.com/...","sizes":["S","M","L"]}]}

event: text_chunk
data: {"delta":"I found the Juventus 2019/20 Home Kit in stock! Would you like me to add size L to your cart?"}

event: done
data: {}
```

### How React Renders This:
1. **The Chat Message Component** inspects the incoming stream chunks.
2. If `ui_component` arrives, React dynamically renders an interactive `<ProductCarousel />` or `<JerseyCard />` component right inside the chat bubble.
3. The customer can click buttons on that card (e.g., select a size, click "Add to Cart") without ever leaving the conversation.
4. As text chunks arrive, they typewriter-stream directly below the interactive card.

## 4. Custom Jersey Name & Numbering (2D Interactive Canvas)

In [schema.prisma](file:///d:/Projects/ShopMate_AI/backend/prisma/schema.prisma#L171-L173), every cart item supports:
```prisma
customName   String?   // e.g., "HENRY"
customNumber Int?      // e.g., 14
sleeveBadge  String?   // e.g., "Champions League Starball"
```

### Why Interactive 2D SVG/Canvas Instead of 3D?
* **3D Models (Three.js / WebGL):** Require dedicated 3D `.glb` digital asset meshes for all 24 historical kits. Since free 3D models for vintage kits do not exist on the open web, full 3D would result in broken textures and missing models.
* **The Production Solution (Dynamic SVG Kit Studio):**
  1. The user (or the agent via tool call) activates "Customizer Mode".
  2. The UI displays the back view of the official jersey render.
  3. An SVG coordinate layer dynamically scales athletic typography (curved player name across the shoulder blades, prominent back number, and sleeve badge).
  4. The preview updates instantly at 60 FPS as the user types or as the agent selects options.

## 5. Developer Checklist: Key Rules & Guardrails

When working on any part of the AI pipeline, keep these critical engineering rules in mind:

1. **Server-Authoritative Pricing:**
   The AI agent **never calculates or promises prices independently**. All pricing must be calculated by our backend pricing service from database numbers ($15 name/number, $5 badge). The agent only reads what the server computes.
2. **Strict Inventory Gating:**
   The agent must never execute `addToCart` without first verifying `stockQuantity >= requestedQuantity`. If stock is 0, the agent must inform the user and suggest alternative sizes or similar kits.
3. **Zod Validation on All Tool Inputs:**
   LLMs can occasionally output malformed JSON or unexpected arguments. Every tool function must wrap its inputs in strict Zod schemas before running any Prisma query.
4. **SSE Connection Resilience:**
   Always handle client abort signals (`req.on('close')`) to terminate active Gemini streaming sessions and prevent memory leaks.
5. **No Hallucinated URLs:**
   All image URLs returned by the agent must originate from verified database rows (`jerseys.images` or `clubs.logoUrl`), never generated out of thin air by the LLM.
